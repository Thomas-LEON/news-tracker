# Standard Operating Procedure (SOP): Cyber Threat Intel News Tracker

This document outlines the operation, architecture, and maintenance procedures for the **News Tracker** project, an automated, AI-driven pipeline for the collection, synthesis, and distribution of Cyber Threat Intelligence (CTI).

---

## 1. Project Architecture

The project is hosted on GitHub and runs daily via GitHub Actions.

### Folder Structure
`	ext
news-tracker/
├── .github/workflows/
│   └── daily-tracker.yml     # GitHub Actions workflow (Cron at 06:00 UTC)
├── data/
│   ├── incidents_db.json     # JSON database storing incident metadata
│   └── controls_db.json      # JSON database storing security controls
├── newsletters/              # Formatted email reports

`

## 2. Execution Flow (The 
ews_tracker.py Pipeline)

The 
ews_tracker.py script follows a strict sequential pipeline to guarantee zero hallucinations and maximum relevance:

1. **RSS Extraction (Scraping)**: The script queries a predefined list of cybersecurity RSS feeds (The Hacker News, Dark Reading, etc.). A 15-second network timeout is configured to prevent hanging.
2. **Deduplication Filtering**: The script reads the .md files in the eports/ folder from the last 3 days to ignore articles with similar titles.
3. **Drafting (LLM 1)**: The list of articles is sent to the Google Gemini API. The prompt enforces:
   - The extraction of the "News Nature" (Vulnerability, Attack, Patch, etc.).
   - The strict rejection of rumors or standard IT outages (e.g., non-cyber CrowdStrike outages).
   - **Strict Risk Metrics Evaluation (CRQ / FAIR Methodology)**: The LLM evaluates the day by scoring the most critical incident across three criteria from 1 to 10. Strict thresholds are defined as follows:
     - *Threat Capability (TC):* 
       - 1-3: Known/patched vulnerability / Basic attack.
       - 4-7: Sophisticated attack requiring human action.
       - 8-10: Critical Zero-Day under active exploitation, Zero-click, Nation-State.
     - *Event Frequency (EF):*
       - 1-3: Does not target the banking/AI sector at all.
       - 4-7: Opportunistic global campaign (the bank could be hit).
       - 8-10: The financial sector or the bank's Cloud/AI infrastructure is the direct target.
     - *Business Impact (BI):*
       - 1-3: Negligible impact, minor service disruption.
       - 4-7: Prolonged downtime, non-critical data theft.
       - 8-10: Global systemic risk, massive financial data theft, bankruptcy.
   - **Threat Score Calculation (0 to 100)**: The Python script intercepts these three scores and calculates a deterministic overall score using the formula Score = (TC + EF + BI) * 3.33. A color code is applied: 🟢 (≤ 50), 🟠 (51-75), 🔴 (> 75).
4. **Audit & Fact-Checking (LLM 2)**: A second LLM call verifies the draft report generated by the first one. It ensures there are no hallucinations, format compliance, and temporal consistency.
5. **"SKIPPED" Status Handling**: If the AI determines there is no relevant or major news, it returns "SKIPPED" and the script cleanly exits without publishing anything.
6. **Conversion & Export**: 
   - Saves the Markdown format in eports/.
   - Converts the Markdown to HTML.
   - Encapsulates the HTML into an .eml file with MIME headers in 
ewsletters/.
7. **Database Updates**: The data/incidents_db.json and data/controls_db.json files are updated with the extracted metadata.

## 3. Configuration and Environment Variables

The script relies on crucial environment variables, configured in GitHub Secrets for automation:

| Variable | Description | Default Value |
|---|---|---|
| GEMINI_API_KEY | API key to access Google Gemini models | N/A (Required) |
| OUTPUT_FORMAT | Output format for the newsletter file | html (generates an .eml) |

*Network Note (Proxy)*: The script uses httpx.Client(verify=False) to bypass TLS interception tied to corporate proxies (e.g., Zscaler).

## 4. Maintenance & Standard Operations

### A. Add a new news source
To add an RSS feed:
1. Open 
ews_tracker.py.
2. Locate the RSS_FEEDS list.
3. Add the URL of the new RSS feed to the list.

### B. Modify the Evaluation Grid (Threat Score)
The *Threat Score* calculation is handled directly within the LLM prompt. To adjust its severity:
1. Find the THREAT SCORE RUBRIC section in the first prompt.
2. Modify the scoring criteria directly in the text prompt.

### C. Emergency Format Rollback
If the .eml format breaks or does not render well in the email client, modify the OUTPUT_FORMAT environment variable on the GitHub Actions runner to markdown. The script will revert to its original plain markdown output behavior.

## 5. Troubleshooting

- **Issue: GitHub Actions Workflow loops infinitely.**
  - *Cause*: Automated commits are re-triggering the action.
  - *Solution*: Ensure that the git commit -m "... [skip ci]" line correctly includes [skip ci].
- **Issue: Gemini Timeout Error (ReadTimeout).**
  - *Cause*: The Gemini API takes too long to respond to very long prompts.
  - *Solution*: The script already handles a 	imeout=360.0 (6 minutes). If it recurs, check Google's service status. The script includes fallback logic to smaller models (gemini-3.1-flash-lite) if the main model fails.
- **Issue: The same news repeats day after day.**
  - *Cause*: The deduplication system relies on exact title matches in the Markdown files of the past 3 days.
  - *Solution*: Verify that previous reports were not accidentally deleted from the eports/ folder.
- **Issue: Push Error (Merge Conflict) during GitHub Actions run.**
  - *Cause*: Manual commits were made to the repo while the action was running.
  - *Solution*: The workflow uses git pull --rebase origin main before pushing to mitigate this risk. Avoid committing between 06:00 and 06:10 UTC.
